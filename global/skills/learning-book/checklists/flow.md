# Flow checklist

Flow breaks where parallel workers and fix rounds edit a section without reading its
neighbors. After every batch, build the book and read each changed section with the
sections around it. After drafting a part, and before each blind read, read the whole
book in order.

- Each chapter's sections serve the goals it opens with, and the reader can do each goal
  from the text: a needed config file or setup step is shown.
- The running example keeps its names and schema unless the text announces a change.
- Exercises come after the rules they need, and no passage relies on a later idea.
- A case is told in one place, and an idea is explained once under one name.
- Framings match the plan's scope statement; search for the narrower ones that drift in,
  such as "the service" in a book about a whole application.
